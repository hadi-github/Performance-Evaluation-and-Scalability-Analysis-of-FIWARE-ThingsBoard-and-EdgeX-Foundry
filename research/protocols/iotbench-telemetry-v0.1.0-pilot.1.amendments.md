# IoTBench telemetry contract pilot.1 — scoped amendment record

This is an append-only decision record for the preliminary executable contract `iotbench-telemetry-v0.1.0-pilot.1.json`. It does not amend or replace D44, the dated offline profile policy, preregistration archives, or the campaign protocol. Add future amendments as dated entries; never rewrite prior entries.

## 2026-11-03 — preliminary executable contract foundation

- **Status:** engineering pilot only; `freeze_status=pending_calibration`. Campaign use fails closed.
- **Profile binding:** explicitly references `offline-profiles-20261101.json` by SHA-256. Its Quick delivery 500 ms primary, 250/1000/5000 ms sensitivities, saved-data reliability, and high-device-count comparison semantics remain unchanged. This file does not resolve missing live reference/capture/qualification evidence.
- **Metric proposal:** unique first observed receipts for the scheduled half-open measurement cohort; nearest-rank p50/p95/p99; ERROR/UNKNOWN and drain arrivals through an explicit cutoff remain in the observed cohort; conditional-on-observed percentile is always accompanied by scheduled/observed/missing and threshold attainment. Missing has no finite latency. Capture invalidity is not platform missing; identifiable corruption remains observed. Ack-only and scheduled-to-response stay separate.
- **Outcome proposal:** preserve D15 `iterationInTest` identities and zero-drop validity. `NOT_SENT` requires positive identified non-submission evidence. A dropped count is separate and does not create an exact slot ledger; that remains an unsatisfied capability for dropped INVALID runs.
- **Logical payload recommendation:** `logical-json-ascii-v1`, ordered fields and versioned deterministic hex padding. The current Go/k6 data source uses the same Mix salts/ranges (temperature 15–45, humidity 30–80, pressure 950–1150); k6 already creates scheduled timestamps rounded to millisecond precision. The new encoder itself does not round: it accepts at most three fractional decimal digits and rejects unsupported values. Proposed sizes are unpadded baseline plus 1024 and 4096 bytes, not adopted/qualified. Adapter-specific wire encodings are not changed.
- **Replica mapping:** proposes independent K∈{1,2,3} CPU-budget and N∈{1,2,3} replica dimensions. Named service maps use N for ThingsBoard core/rule-engine/http-transport, FIWARE Orion/IoT Agent, and EdgeX core-data/device-rest; EdgeX app-http-export remains a singleton. This is a mapping proposal, not evidence of coordinated/qualified scaling.
- **Retained sourced controls:** strict 2× headroom, 300 s warm-up, 600 s confirmation, at least five independent repetitions. Clock budget, drain/recovery windows, sample counts, backlog epsilon, capacity-full/search predicate and scientific D/rate grid remain pending calibration/ratification. The 1.5×/180 s, ≤5% bisection, five endpoint repeats proposal is labeled separately and is not adopted; no optional favorable stopping and no hybrid search are frozen.
- **Receipt handling:** complete-body-read-before-parse is a proposal for a future sink/receiver amendment; no sink behavior was modified here.
- **Implementation boundary:** strict parser, source-byte hash, explicit run binding/eligibility checks, platform design model, metric/outcome helpers, canonical payload and stored-byte validator are implemented in `internal/protocol`; a pure k6-compatible reference lives in `workloads/k6/lib/payload.js`. Existing plan, analyzer, adapters and sink are not yet consumers. This is intentionally not the one-protocol integration gate.

No deployment, sink change, live test, broad analyzer migration, campaign freeze or scientific grid freeze was performed.

## 2026-11-03 — independent review fix amendment (M0b-R1…R7)

- Strict decoding now rejects duplicate object keys before typed decode, rejects omitted/null/changed normative payload and receipt-capture semantics, and requires exact outcome-state sets. Receipt-capture metadata is a typed structure. This does not add any sink implementation.
- The loaded definition is source-byte-bound behind private fields; its accessor returns a fresh decode. Eligibility rechecks source/profile hashes and this pilot.1 contract categorically rejects campaign execution, regardless of caller evidence-reference labels. Those labels remain non-attesting metadata.
- Stored-content validation requires all eight typed, non-null fields and rejects duplicate keys. Go checks raw JSON tokens before decoding. JavaScript exposes a raw-text/bytes validator with duplicate-key scanning; callers that already called `JSON.parse` cannot recover duplicates and must not claim that check.
- Timestamp acceptance uses exact decimal-scale inspection of shortest numeric serialization for in-memory values and the supplied raw JSON number token for stored bytes; no multiply-and-tolerance rule. At most three effective fractional places, safe-integer magnitude, and no rounding. Negative zero is normalized to canonical positive zero in both implementations.
- JS identifiers must be strings before pattern checking. Payload maximum applies to encoded body bytes, not half that number of hex characters. ASCII-hex padding changes size by two bytes at a time, so only targets with the unpadded baseline's parity are representable; target is still bounded by 1 MiB. Baseline+1024/+4096 remain proposals.
- Engineering-pilot rate must be finite and positive. These fixes do not implement cohort selection: nearest-rank/attainment helpers still consume caller-selected unique first-receipt latencies, and no cohort-membership or evidence-completeness implementation is claimed.
- The numeric timestamp bound is the cross-language safe integer maximum `9007199254740991`; effective decimal scale is computed from the exact raw JSON token for stored values and each language's shortest numeric serialization for typed values. The maximum body and parity rule are normative; an odd-byte increment is not representable by ASCII-hex padding.
- Stored timestamp tokens must match the shortest canonical numeric serialization after decoding, preventing a high-precision token from being silently rounded into a matching float; exact numeric-zero spellings (including negative zero) normalize to canonical `0`.

## 2026-11-03 — second independent-review amendment (M0b-R1/R3/R4/R6)

- Protocol objects now require exact case-sensitive field names and exact required key sets before Go struct decoding; duplicate keys and case-folded aliases are rejected recursively. `payload.field_order` is checked as eight exact array elements. Retained policy objects are closed schemas with exact source anchors and values; pending-calibration entries are non-null and exact.
- Stored `seq`, temperature, humidity, and pressure require canonical integer JSON tokens before decoding in Go and JS. Decimal/exponent spellings cannot round, overflow, or underflow into matching integer values.
- Timestamp coefficient-zero detection is based on decimal digits, never float conversion. Exponent magnitude above 10000 is rejected, and nonzero values that underflow or otherwise cannot be represented are rejected before canonical comparison. Exponent/scale arithmetic is bounded to avoid integer overflow; numeric-zero spellings remain normalized to `0`.
- `ValidateStored` now checks every `CanonicalBytes` error for expected and actual payloads before comparing encoded bytes; payloads whose encoded body exceeds 1 MiB cannot become equal merely because both encodings failed. Padding character count itself remains bounded, while the complete encoded body limit applies to both sides.
