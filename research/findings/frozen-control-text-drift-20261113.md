# Two frozen control files carry text that no longer matches the live decision

**Date:** 2026-11-13
**Status:** DOCUMENTED, DELIBERATELY NOT APPLIED.
**Scope:** documentation only. No control file was changed, no receipt invalidated, no run affected.

Two fields in the frozen W-batch controls still read as if a decision were open when it
has since been made. Both were considered for correction and both were **left exactly as
they are**, because the correction is more expensive than the inconsistency.

This note records why, so the next person does not "fix" them and silently invalidate a
receipt.

---

## 1. `scope.json → edgex_inventory_budget` is a frozen projection, not the live policy

```json
"edgex_inventory_budget": {
  "new_experimental_cohort_devices": 25000,
  "projected_retained_after_original_b0": 11192,
  "projected_total_before_new_qualifications": 36192,
  "previous_discovery_limit": 16384,
  "status": "BLOCKED_PENDING_LIVE_INVENTORY_AND_COMMON_DISCOVERY_CONFIGURATION_REVIEW"
}
```

The live policy is not this block. The launcher passes
`EDGEX_INVENTORY_RESERVE=<actual cohort>`, and
`deploy/edgex/scripts/provision-then-scale.sh` already falls back to the cohort when the
variable is unset. The 25,000-device projection is the number that *prompted* the block;
it was never the reserve.

**Why it was not edited.** `scope.json`'s SHA-256 (`70be4f5f…`) is bound in two places:

| Binding | Where |
|---|---|
| `run-matrix.json → scope_sha256` | checked by `scripts/workload-campaign.py` |
| `bindings_sha256.scope` in every owner-authorization receipt | includes the **unused** EdgeX W3 receipt `owner-w3-qual-ex-20261112e3` |

Changing one byte invalidates the matrix binding and every receipt, for an edit that
changes no behaviour. That trade is not worth taking.

## 2. `qualification-gates.json → other_configuration_headroom` is a string among lists

Every other key in that file is a **list of gate strings**:

```json
"W1": ["…", "…"],
"W2": ["…"],
"W3": ["…"],
"W4": ["…"]
```

`other_configuration_headroom` is a bare string:

```json
"other_configuration_headroom": "Qualify applicable 50/s headroom for D=2000, padding=1024 or N=1/k=2, …"
```

Code that iterates the file as `for gate in gates[key]` will walk that value **character by
character**. That is a real shape bug, and it surfaces the first time someone writes a
generic loop over the gates.

**Why it was not edited.** The file is generated by `scripts/stage-fixed-point-variants.py`
(line 177), whose SHA-256 (`9d82b7c5…`) is itself bound in
`bindings_sha256.variant_stager` of the same unused EdgeX W3 receipt. Fixing the shape in
the *generated file* alone would be undone the next time the stager runs; fixing it in the
*stager* drifts the receipt.

If this is worth fixing, do it as a deliberate step that also re-records the affected
receipt — not as a drive-by documentation edit.

## 3. The literal "50/s" clause

`other_configuration_headroom` says *"qualify applicable **50/s** headroom"*, while W2,
W3 and W4 are frozen at **25/s**. The sentence was written before the rates were fixed. As
written it asks for qualification at a rate the configurations do not use.

This is the one item here that is a genuine question rather than a shape artifact, and it
is an **owner decision**, recorded as open:
does the headroom clause bind W2/W3/W4 to a 50/s qualification they never run, or does it
mean "qualify headroom for whatever rate the configuration actually uses"?

Until the owner settles it, the prudent reading is the second: W2, W3 and W4 qualifications
at 25/s are the applicable shape, and a 50/s headroom claim is not implied for them. That
reading is stated here rather than written into the frozen file.

---

## Rules this note establishes

1. A frozen control file is not a document. Do not edit one to make prose read better.
2. Before editing anything under `workloads/campaigns/`, check whether its hash is bound by
   `run-matrix.json → scope_sha256` or by any `authorization/*.json → bindings_sha256`.
3. If a frozen value is wrong in a way that matters, the fix is *value + new receipt*, done
   deliberately, never a silent edit.
