# Monitoring: Prometheus + Grafana on the load generator, exporters on the SUT

```
ramonavm1 (load generator, 4 vCPU)                   ramonavm2 (SUT, 8 vCPU)
  k6 (cores 0-2) ──remote write──► Prometheus ──scrape──► node-exporter :9100   (host)
                                   (core 3, 127.0.0.1)   cAdvisor      :8089   (every container: CPU, memory, OOM)
  Grafana :3000 (core 3) ◄─────────┘                    HAProxy       :8404   (per backend and per replica)
  node-exporter (127.0.0.1:9100) ◄─┘                     postgres-exporter :9187  (ThingsBoard / EdgeX)
                                                         kafka-exporter    :9308  (ThingsBoard)
                                                         mongodb-exporter  :9216  (FIWARE)
                                                         nats-exporter     :7777  (EdgeX)
```

## Deploy

On **ramonavm1** (`monitoring/`):

```bash
cp .env.example .env && sed -i "s|^GF_ADMIN_PASSWORD=.*|GF_ADMIN_PASSWORD=$(openssl rand -base64 18)|" .env
docker compose up -d
```

Grafana: `http://<ramonavm1>:3000` (user `admin`, password in `.env`). Its home dashboard is **IoT benchmark
overview**. Prometheus listens on 127.0.0.1:9090 only (use an SSH tunnel: `ssh -L 9090:127.0.0.1:9090 ramonavm1`).
All three containers use the host network, so k6 and Grafana reach Prometheus on localhost.

On **ramonavm2** (`monitoring/exporters/`), after the platform is up (the exporters join its Docker network):

```bash
make up P=fiware        # or thingsboard / edgex; base exporters (node, cAdvisor) + that platform's ones
make down               # all exporters
./firewall.sh install   # once: monitoring ports accept only ramonavm1 (re-applied after every Docker start)
```

Only one platform runs at a time, so in Prometheus the exporters of the other two are DOWN. That is expected.

## Resource isolation

- SUT: all exporters are pinned to **core 0** (the OS core) with memory limits, outside HAProxy (1),
  infrastructure (2-3) and the platform pool (4…). Their cost is shown on the overview dashboard ("Exporter
  overhead"). cAdvisor keeps only the compose project/service labels and the cpu, memory, network, oom_event and
  diskIO metric groups (`--housekeeping_interval=5s`).
- Load generator: k6 on cores 0-2, Prometheus/Grafana/node-exporter on core 3. "Load generator busy per core" on
  the overview shows whether ramonavm1 itself is the limit.
- Prometheus scrapes every 5 s (10-minute runs need fine-grained samples) and keeps 30 days.

## Clocks

The SUT health check in `workloads/run.sh` compares container start times (SUT clock) with the run window
(load-generator clock), so both hosts must be NTP-synchronised. ramonavm1 cannot reach the Ubuntu NTP servers
abroad. It uses `ir.pool.ntp.org` / `ntp.day.ir` via `/etc/systemd/timesyncd.conf.d/iran.conf`.
